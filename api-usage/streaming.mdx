The i14 API supports streaming responses via Server-Sent Events (SSE). With streaming enabled, tokens arrive as they're generated instead of waiting for the full response — making your application feel faster and allowing you to display output progressively as the model thinks.

## Enable Streaming

Add `"stream": true` to your request body to enable streaming. The API will keep the connection open and push chunks of data as the model produces them.

Use `--no-buffer` with curl to disable output buffering and see each chunk as it arrives:

```bash
curl https://api-dev.i14.ai/v1/chat/completions \
  --no-buffer \
  -H "Authorization: Bearer $I14_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{
    "model": "sugar-glider-120b",
    "messages": [
      { "role": "system", "content": "You are a helpful assistant." },
      { "role": "user", "content": "Write a short poem about the ocean." }
    ],
    "stream": true,
    "max_tokens": 256
  }'
```

## SSE Response Format

When streaming is enabled, the API responds with a series of `data:` lines, each containing a JSON object. Each chunk carries a `delta` object inside `choices[0]` rather than a full `message` object. The `content` field of the delta holds the next token or tokens in the response.

Once the model finishes generating, the stream ends with a special sentinel line:

```
data: [DONE]
```

Here is a sample of what the raw SSE output looks like:

```
data: {"id":"chatcmpl-a1b2c3","object":"chat.completion.chunk","model":"sugar-glider-120b","choices":[{"index":0,"delta":{"role":"assistant","content":""},"finish_reason":null}]}

data: {"id":"chatcmpl-a1b2c3","object":"chat.completion.chunk","model":"sugar-glider-120b","choices":[{"index":0,"delta":{"content":"The"},"finish_reason":null}]}

data: {"id":"chatcmpl-a1b2c3","object":"chat.completion.chunk","model":"sugar-glider-120b","choices":[{"index":0,"delta":{"content":" ocean"},"finish_reason":null}]}

data: {"id":"chatcmpl-a1b2c3","object":"chat.completion.chunk","model":"sugar-glider-120b","choices":[{"index":0,"delta":{"content":" whispers"},"finish_reason":null}]}

data: {"id":"chatcmpl-a1b2c3","object":"chat.completion.chunk","model":"sugar-glider-120b","choices":[{"index":0,"delta":{},"finish_reason":"stop"}]}

data: [DONE]
```

Parse each `data:` line as JSON, extract `choices[0].delta.content`, and append it to your output buffer. Skip any chunk where `delta.content` is absent or empty.

## Streaming with the OpenAI SDK

The OpenAI SDK handles SSE parsing for you. Set `stream=True` (Python) or `stream: true` (Node.js) in your request and iterate over the returned stream object to access each content delta.

<CodeGroup>

```python Python
from openai import OpenAI

client = OpenAI(
    api_key="YOUR_I14_API_KEY",
    base_url="https://api-dev.i14.ai/v1",
)

with client.chat.completions.create(
    model="sugar-glider-120b",
    messages=[
        {"role": "system", "content": "You are a helpful assistant."},
        {"role": "user", "content": "Write a short poem about the ocean."},
    ],
    stream=True,
    max_tokens=256,
) as stream:
    for chunk in stream:
        content = chunk.choices[0].delta.content
        if content is not None:
            print(content, end="", flush=True)

print()  # newline after stream ends
```

```javascript Node.js
import OpenAI from "openai";

const client = new OpenAI({
  apiKey: "YOUR_I14_API_KEY",
  baseURL: "https://api-dev.i14.ai/v1",
});

const stream = await client.chat.completions.create({
  model: "sugar-glider-120b",
  messages: [
    { role: "system", content: "You are a helpful assistant." },
    { role: "user", content: "Write a short poem about the ocean." },
  ],
  stream: true,
  max_tokens: 256,
});

for await (const chunk of stream) {
  const content = chunk.choices[0]?.delta?.content ?? "";
  process.stdout.write(content);
}

process.stdout.write("\n");
```

</CodeGroup>

<Tip>
  Use streaming in chat UIs and long-form generation tasks to improve perceived latency. Instead of waiting several seconds for a complete response, your users see the first tokens within milliseconds — making the experience feel significantly more responsive.
</Tip>
